\begin{abstract}
\setlength{\parindent}{2em}
本报告面向国产芯片上的大模型推理吞吐优化任务，在官方指定的 FlagOS 栈上，对 MiniCPM5-2B 在天数 BI-V150 与沐曦曦云 C500 两款芯片开展算子、内核与调度优化，保持 \texttt{vllm serve} 启动参数、模型与精度要求不变。天数最终版本已从公开 tag 历史重放到官方镜像实际基线 FlagGems \texttt{4df52d91}，避免以公开 tag 的后续提交替代镜像基线。

在已完成的同机复测中，C500 的 4k 与 16k 总吞吐分别为 12527.62 和 11143.77 tok/s，达到官网基线的 2.46 倍和 1.59 倍。天数 BI-V150 的官方开发与评测环境均为 32GB；镜像对齐后，4k 三次独立四轮测量中位数为 5292.46 tok/s，TTFT 为 3908.25 ms，16k 四轮汇总为 4618.41 tok/s，TTFT 为 118761.15 ms，分别达到官网基线的 2.61 倍和 5.05 倍。最终 MATH-500 Level 3 为 98.1\%（105/105 成功、0 错误），高于 95\% 的赛题要求。

主要优化包括：按输入形状选择 GEMM 与 attention 的实现或执行配置；用 1024-bin 质量直方图实现免排序 top-p 采样；针对 PV 矩阵乘的布局转换开销重写 paged decode attention；通过双累加器 GEMM 融合 SiLU 门控，并将 gate/up 权重预打包为 K 维连续的 tile；通过进程内配置缓存和单表反射减少 host 配置查询与数据库反射开销；减少 prefill 阶段的隐式同步与冗余内核发射。

\noindent\textbf{关键词：}国产芯片；推理吞吐；算子融合；paged decode attention；shape-aware dispatch；vLLM
\end{abstract}

\section{引言}
在硬件、框架和模型固定的条件下，推理吞吐主要受内核效率、访存布局、host 发射和同步开销影响。本报告以 MiniCPM5-2B\cite{minicpm} 为对象，在天数 BI-V150 与沐曦曦云 C500 上，基于官方指定的 FlagOS 软件栈（vllm-plugin-FL\cite{vfl} 与 FlagGems\cite{fg}）开展优化。

两种芯片在指令集、访存层次、运行时和算子库方面存在差异，通用 GPU 上的常用配置不一定适用。例如，Triton 默认的 \texttt{num\_warps=4, num\_stages=3} 在 BI-V150 的 decode attention 上并非合适选择。优化过程先用 profile 和微基准定位瓶颈，再修改内核或执行路径，最后通过官方 benchmark 和 MATH-500 评测端到端效果。后续章节分别介绍 C500 的采样链与 GEMM 路由、BI-V150 的 attention 接入与 decode 内核，以及正确性和复现方法。

\subsection{任务定义}
本赛题要求在不改变模型、不降低精度的前提下，提升 MiniCPM5-2B 在两指定国产芯片上的推理总吞吐（total tokens/s）。优化必须落在框架与算子内部，且需具备实际开发量：KV Cache 与动态批处理、算子融合、内核重写、自研量化策略等均在允许范围内；直接 merge 上游分支、修改 benchmark 脚本、或在缺乏算子优化的情况下切换算子均被禁止。

\subsection{主要技术贡献}
本提交的技术路线由以下五部分组成，详细实现和实验分别见第 4、5 章。

\textbf{（1）面向芯片与输入形状的执行路径选择。} 不假定同一 GEMM 或 attention 配置在所有形状上最优，而是在保留原实现的前提下，按 M、KV 页尺寸和 prefill／decode 类型选择 vendor 库或 Triton 内核。C500 侧重 lm\_head 与 prefill GEMM 的布局、库调用和 host 元数据路径；BI-V150 侧重 warp 级发射配置与 attention 实现。路由之外还包含权重复本、布局转换、同步消除和页对齐访问等代码改动。

\textbf{（2）免排序 top-p 采样与温度折叠。} 将 bf16 logits 读取、top-p 阈值估计、掩码与 Gumbel-Max 合并，避免对 130560 词表进行完整排序。阈值由 1024-bin 质量直方图定位并保守取 bin 下沿；温度通过 $\arg\max(x/T+g)=\arg\max(x+Tg)$ 折叠进采样分数。该路径直接作用于每步解码末尾的采样热点。

\textbf{（3）减少 PV 布局转换的 paged decode attention。} 针对 BI-V150 上 PV 矩阵乘的累加器到操作数布局转换，将并行单元组织为 warp 内的（序列、KV 头、分段）计算，配合单 warp 发射、base-2 在线 softmax 和分段归并。段边界与 KV 页对齐后，页号在段内保持标量，省去逐 token 除模和向量页 gather；段长由设备端 \texttt{seq\_lens} 计算，分段缓存在图捕获前分配，以兼容 FULL\_DECODE\_ONLY。

\textbf{（4）面向配置与 host 路径的开销消除。} 对同一 shape 的算子配置查询和缺失结果做进程内缓存，避免重复访问配置数据库；将新配置模型的全库 automap reflection 改为只加载目标表。该路径不改变算子选择、数值语义或启动参数，直接减少执行线程中的配置与元数据开销。

\textbf{（5）门控融合与权重 tile 预打包。} BI-A48 以两个 FP32 累加器共享输入 tile，直接输出 SiLU 门控结果；BI-A60 进一步把 gate/up 权重预打包为 K 维连续的 \(BK\times BN\) tile，使加载布局匹配 BI-V150 的 \texttt{tl.dot} 后端。预打包只执行一次并缓存，不在 decode 稳态重复转换权重。

\subsection{自研 paged decode attention 内核（BI-A20）}

\subsection{配置缓存与单表反射（BI-A31）}

\subsection{双累加器门控融合与 K 连续权重预打包（BI-A48／BI-A60）}
BI-A48 使用两个独立的 FP32 累加器分别计算 gate/up，共享 A tile 加载，并直接写出 \(gate\cdot\mathrm{sigmoid}(gate)\cdot up\)，避免中间激活的额外读写。官方 4k 两组中位数由 5201.98 增至 5237.32 tok/s（+0.679\%），16k 由 4524.55 增至 4556.53 tok/s（+0.707\%），两种场景的 TTFT 均改善，MATH-500 Level 3 为 98.1\%。

BI-A60 保留上述数值路径，仅改变 B 矩阵的物理布局。设 \(BK=32\)、\(BN=128\)，gate/up 分别重排为 \([K/BK,N/BN,BN,BK]\)，即同一 tile 内的 K 维连续。内核以 \([BK,BN]\) 逻辑形状执行 \texttt{tl.dot}，写回时使用全局 \texttt{rn} 偏移；K、N 可整除时进入该路径，否则回退 A48。预打包结果按权重地址、设备、dtype、形状和 stride 缓存，缓存项保留原权重引用，稳态 decode 不重复转换。

\subsection{复现注意事项}
（1）检查 prefix cache：benchmark 使用 seed=0，同一 serve 上重复相同 input\_len 的负载可能命中 prefix cache；本队日志出现过 35.9\% 命中率，并伴随 prefill 开销降低和吞吐虚高。旧日志不能证明各次运行均无命中，因此每个数据点都须检查命中率日志，必要时在新启动的 serve 上测量。各次最终复测的命中率低于 1\%。

（2）C500 需要 $\geq$128 GB CPU 内存：在模力方舟 64 GB 内存规格实例上，纯镜像原版 \texttt{vllm serve} 也会在 inductor 编译阶段被 cgroup OOM killer 杀掉（匿名内存峰值 63.4 GB，被杀时 GPU 显存仅 858 MiB，与显存、负载、代码改动均无关）。128 GB 规格实例全程稳定。

（3）启动耗时：C500 需执行 GEMM autotune 预热。实测记录约 127–1129 秒，原生基线为 161 秒；预热时间随实例和缓存状态变化，不能用固定秒数估计。

（4）测量波动：C500 实测版本 4k 后三轮吞吐极差为 0.80\%，16k 为 0.29\%。BI 最终版本的三次 4k 独立四轮测量为 5131.78／5292.46／5292.99 tok/s，首测受设备冷态影响，报告采用中位数并保留全部三次结果；16k 单次四轮测量为 4618.41 tok/s，与旧实例基本一致。C500 同时保留官网与本机原生基线，避免跨实例参照混淆。

\section{结论}
本文在官方 FlagOS 栈上完成了 MiniCPM5-2B 的双平台推理优化。C500 的主要收益来自采样链融合、GEMM 路由和 prefill 同步消除；BI-V150 的主要收益来自 vendor attention 接入、发射配置调整、paged decode attention 重写、配置/host 开销消除、门控融合和 K 连续权重预打包。C500 已完成的复测中，4k 与 16k 吞吐分别为官网基线的 2.46 倍和 1.59 倍，为本机原生基线的 2.98 倍和 1.90 倍。BI 最终栈在官方镜像基线重放后，4k 三次独立四轮测量中位数为 5292.46 tok/s，16k 为 4618.41 tok/s，分别为官网基线的 2.61 倍和 5.05 倍。C500 两次 MATH-500 均为 98.1\%，BI 最终栈为 98.1\%，均满足赛题要求。

C500 已完成复测的 4k TTFT 为 1623.73 ms，16k TTFT 为 17961.76 ms，均优于官网和本机原生基线；BI 最终栈的 4k TTFT 为 3908.25 ms，16k 为 118.76 s，均满足官网 TTFT 上限。BI 的首次 4k 测量为 5131.78 tok/s，随后两次稳定在 5292 tok/s 以上，报告保留该波动。后续可继续研究 prefill 分块策略和编译器融合，并在更多国产芯片上检验这些实现的适用性。
