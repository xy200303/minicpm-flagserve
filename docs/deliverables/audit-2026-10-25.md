# 技术报告事实与代码一致性审计（2026-10-25）

## 范围与判定方式

审计对象为 `docs/deliverables/latex/main.tex`、绘图脚本、提交版 `readme.md`，以及提交包中的插件 `0207b7e1` 和算子 `dd574fdd`。逐项对照 `docs/baselines/`、`docs/experiments/`、原始 CSV／JSON／日志和交付代码。

本文件区分五类结论：

- **一致**：数值、代码和引用口径一致。
- **口径需限定**：数字有来源，但报告混淆了版本、实例、测量方式或指标定义。
- **证据不足**：只有文字转录或摘要，缺少可独立复核的原始工件。
- **明确错误**：数字、算术、代码行为或文件存在性与报告冲突。
- **建议复测**：静态材料不足以支撑最终交付版本的关键结论。

官网赛题页于审计当日重新读取，确认了官方 serve 参数、4k/16k 用例、精度门槛和四轮 benchmark 入口。官网基线表是图片，DOM 文本没有表内数字；当前官网基线数值仍来自已有登记，复测时保留官网基线图作为外部参照。

## 已核对一致的内容

- 两个交付目录 HEAD 与报告提交号一致，工作树干净。
- 十个 minted 引用均指向实际代码；需要扩大三处窗口以包含完整路由分支、metadata 缓存写入和双 gather 函数边界。
- C500 opt7、opt8、opt10、opt11 的 summary CSV 数值及相邻版本百分比算术一致。
- C500 图14 的算子族时间与占比可复算；但它只对应 opt1 前后。
- C500 四种 prefill GEMM 的 TFLOPS 与 `2MNK/t` 复算一致，vendor 约 152–197 TFLOPS。
- BI A20 最终展示数字来自页对齐版本 B19/B20，不是早期混合步未覆盖时的 16k 负收益版本。
- 最终交付代码包含混合步 decode 调用和页对齐实现。
- A6、A7、A20 在图16中明确为各自当日对照、非累计，这一处理正确。
- NSEG 热力图逐格对应 `a26_sweep.log`；c64/16k 的 NSEG=32 为 2.084 ms、515 GB/s。
- 官方 serve 参数、benchmark 参数、MATH-500 Level 3 和精度门槛与官网一致。

## 最终交付版本的证据缺口

1. 当前 `0207b7e1+aff68555` 没有完整的双平台性能复测工件。
2. BI B19/B20 是历史实验点；后续树只有 B21 的文字记录，没有完整摘要。
3. 两个平台的当前 MATH-500 需要对应同一交付二进制的原始 JSON。
4. BI 页对齐微基准和 9 个测试需要当前交付代码的原始输出。
5. 旧 serve 日志不完整，无法独立确认关键历史点的 prefix cache 命中情况。

## 最小复测方案

### C500（64GB 显存，建议 128GB CPU 内存）

1. 从当前两个集成分支全新 clone，记录 SHA、机器状态、镜像和依赖版本。
2. 保持官网 serve 参数，完整执行官方 4k+16k 脚本；保存四轮 raw CSV、summary、serve log、bench log 和 prefix cache 命中率。
3. 在同一当前代码上执行 MATH-500 Level 3，保存原始 JSON；采样评测至少两次，报告每次结果，不把其他版本的精度并入区间。
4. 重测当前采样链 `eager→fused` 和 lm_head 路由，避免沿用 opt1/opt11 不同阶段的数字。
5. 官网 baseline 作为外部参照；如需要新的同日相对收益，再增加原生 baseline 对照，不能用 opt 系列中间版本替代原生 baseline。

### BI-V150（官方开发与评测均为 32GB）

1. 使用当前两个集成分支，按官网命令和 `FULL_DECODE_ONLY` 启动。
2. 当前版本与 A7 栈关闭 A20 做同日交错 A/B；4k、16k 各至少两组，保留每轮原始工件和命中率。
3. 记录显存容量、KV 池容量和实际并发，统一按官方 32GB 口径分析。
4. 对当前页对齐内核重测 stock／fast 微基准、数值误差、9 个 pytest 用例和混合步路径日志。
5. 对当前版本执行 MATH-500 Level 3，保存原始 JSON。
6. 官网 32GB baseline 与本地 A7 对照分开报告，不再统称 stock。
